การออกแบบข้อมูล

17 ตาราง · PostgreSQL 16 · 3NF — สคริปต์จริงอยู่ที่ backend/sql/schema.sql · ข้อมูลตัวอย่างอยู่ที่ data/*.csv (สมมุติทั้งหมด)

1 · ผังโรงพยาบาล

อาคาร → ชั้น → แผนก → จุด → เส้นทาง · เส้นทางหนึ่งแถวคือหนึ่งทิศทาง ทางเดินสองทางจึงเก็บสองแถว

buildings · floors

  • PK id
  • code A · B · C
  • name_th / name_en
  • FK floors.building_id + level ไม่ซ้ำกัน

departments

  • FK floor_id
  • code B3-LAB
  • color ตรงกับสีป้ายจริงในโรงพยาบาล
  • FK entrance_node_id จุดยื่นบัตรของแผนก

nodes · 48 จุด

  • FK floor_id · department_id
  • kind 17 ชนิด: counter, lab, elevator, ramp…
  • landmark_th/en จุดสังเกตที่คนมองเห็นจริง
  • qr_token QR ติดผนัง · NULL = ไม่ติด
  • is_active ปิดใช้แทนลบ เพราะ visit เก่าอ้างอยู่

edges · 104 ทิศทาง

  • FK from_node_id → to_node_id
  • walk_seconds น้ำหนักกราฟ · ลิฟต์ = เวลารอ
  • turn left / right / straight / back
  • is_accessible false = บันได รถเข็นผ่านไม่ได้
  • status open / closed + เหตุผล

2 · แม่แบบขั้นตอน และการมาโรงพยาบาลจริง

แม่แบบคือแผนกลาง · ตอนเปิด visit ระบบคัดลอกเป็น visit_steps ของผู้ป่วยคนนั้น แก้แม่แบบทีหลังจึงไม่กระทบคนที่กำลังเดินอยู่

pathway_templates · template_steps

  • code DM-FU · WALKIN
  • FK service_point_id → nodes
  • deadline_time + deadline_reason_th
  • est_minutes · wait_after_minutes

template_step_prereqs

  • PK (step_id, requires_step_id)
  • เงื่อนไขลำดับเป็นแถว ไม่ใช่ข้อความ "3;4" — ตรวจการวนซ้ำได้

visits

  • token 32 hex · ลิงก์ใน QR บัตรคิว
  • short_code A017-3K9 พิมพ์เองได้
  • profile JSONB · wheelchair, elderly…
  • current_node_id + position_source
  • expires_at สิ้นวัน · หมดอายุแล้วเปิดไม่ได้

visit_steps · visit_step_prereqs

  • status pending → arrived → in_progress → done / skipped
  • sequence ผลการเรียงลำดับตามเงื่อนไข
  • origin template หรือ added (แทรกหน้างาน)
  • arrived_at · called_at · finished_at เซิร์ฟเวอร์ตั้งเท่านั้น

3 · ผู้ใช้ · การตรวจสอบย้อนหลัง · การแจ้งเตือน

users

  • password_hash bcrypt · ไม่ส่งออก API
  • role registrar · station · admin · executive
  • FK department_id ขอบเขตที่มองเห็น

audit_logs

  • actor_kind user · patient · system
  • entity + entity_id + action
  • from_status → to_status
  • created_at เวลาเซิร์ฟเวอร์ · เขียนได้อย่างเดียว แก้/ลบไม่ได้

notifications

  • FK visit_id
  • message_th / message_en
  • read_at NULL = ยังไม่อ่าน

5 · เหตุผลของรูปแบบข้อมูล

ทำไมถึงเป็น 3NF

  • ชื่อห้องและจุดสังเกตอยู่ที่ nodes ที่เดียว ห้องเปลี่ยนชื่อแก้แถวเดียว
  • อาคาร–ชั้น–แผนกแยกตาราง ไม่เก็บเป็นข้อความ "อาคาร B ชั้น 3"
  • เงื่อนไขลำดับเก็บเป็นแถว ไม่ใช่ค่าหลายค่าในช่องเดียว
  • สีป้ายอยู่ที่แผนก ไม่กระจายซ้ำในทุกจุด

ที่จงใจเก็บซ้ำ และเหตุผล

  • visit_steps คัดลอกชื่อขั้นและเวลาจากแม่แบบ — แก้แม่แบบกลางวันต้องไม่เปลี่ยนแผนของคนที่เดินอยู่
  • sequence เก็บผลการเรียงลำดับไว้ เพื่อให้หน้าผู้ป่วยอ่านตรง ๆ ได้
  • walk_seconds ตั้งเองได้ เช่น ลิฟต์รอ 50 วินาทีแม้ระยะ 0 เมตร
  • ticket_no เก็บไว้เพื่อให้จอสาธารณะอ่านโดยไม่ต้องแตะตารางผู้ป่วย
