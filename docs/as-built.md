# CarePath — เอกสารระบบตามที่สร้างจริง

บันทึกย้อนหลังว่าระบบที่ส่งมอบ *เป็นอย่างไรจริง ๆ* ไม่ใช่ตามที่ออกแบบไว้ตอนต้น
เขียนหลังงานเสร็จ เพื่อให้คนที่มารับช่วงต่ออ่านแล้วทำงานต่อได้โดยไม่ต้องเดา

---

## 1. สรุปหนึ่งย่อหน้า

CarePath บอกผู้ป่วยตลอดวันว่า **ตอนนี้ต้องไปที่ไหน และไปยังไง** โดยคำนวณเส้นทางจากผังโรงพยาบาล
ที่เก็บเป็นข้อมูล ปรับตามความต้องการพิเศษของแต่ละคน และจัดลำดับขั้นตอนให้ทันเวลาที่แพทย์กำหนด
เจ้าหน้าที่แต่ละจุดกดปุ่มเดียวแล้วขั้นถัดไปเด้งขึ้นมือถือผู้ป่วยเอง

**สถานะ** ส่วนหน้าจอทำงานครบวงจรและเผยแพร่แล้ว · REST API และฐานข้อมูลมีโค้ดครบแต่ยังไม่ได้ต่อเข้าด้วยกัน

---

## 2. สถาปัตยกรรมตามที่เป็นจริง

```
ผู้ใช้ ──▶ Cloudflare Worker (static assets)
             │
             ├── หน้าเว็บทั้งหมด 12 หน้า · HTML/CSS/JS ล้วน ไม่มี build step
             ├── ข้อมูลผังถูกฝังในหน้าตอน build (node app/build.mjs)
             └── สถานะระหว่างหน้าจอใช้ที่เก็บข้อมูลในเบราว์เซอร์

backend/ ── Node 24 + Express + PostgreSQL 16   (โค้ดครบ · ยังไม่ได้ deploy)
```

**เหตุผลที่ยังไม่ต่อ API** — Workers รันโค้ดที่เขียนไว้ไม่ได้ 3 จุด (เวลา UTC · CPU ของ bcrypt ·
แคชข้าม isolate) รายละเอียดอยู่ใน `README.md` หัวข้อข้อจำกัด การเดโมด้วยหน้าจอ static
จึงเสี่ยงน้อยกว่าและพิสูจน์ตรรกะได้ครบเท่ากัน

## 3. ข้อมูลเป็นศูนย์กลาง

ทุกอย่างงอกจาก `data/` ไม่มีที่ไหนฝัง hardcode ผัง

| ไฟล์ | แถว | ใช้ที่ไหน |
|---|---|---|
| `nodes.csv` | 50 | ทุกหน้าที่มีแผนที่ · ตรวจผัง · คำนวณเส้นทาง |
| `edges.csv` | 53 คู่ → 105 ทิศทาง | Dijkstra ทุกที่ |
| `departments.csv` | 8 | สีป้าย · ขอบเขตที่ผู้ใช้ role station มองเห็น |
| `templates.csv` + `pathways.csv` | 2 แม่แบบ · 12 ขั้น | แผนภาพแม่แบบ · แผนของผู้ป่วย |
| `users.csv` | 6 | บัญชีเจ้าหน้าที่ (รหัส `demo@1234`) |
| `patients.csv` | 10 | ผู้ป่วยสมมุติ |
| `active-visits.csv` | 7 | ใช้ในหน้าผลกระทบและโต๊ะช่วยเหลือ |
| `node-photos.csv` | 0 | รองรับรูปจริง ยังไม่มีข้อมูล |

ชุดทดสอบอัตโนมัติอยู่ที่ `backend/test/` รวม 20 กรณี ครอบคลุมการคำนวณเส้นทาง การจัดลำดับขั้นตอน
และการอ่านไฟล์นำเข้า · รันด้วย `npm test` ในโฟลเดอร์ `backend/`

`node app/build.mjs` อ่านไฟล์เหล่านี้แล้วสร้าง `map.html` `patient-map.html` `pathway.html`
`impact.html` `station.html` `helpdesk.html` `admin.html` ใหม่ทั้งหมด
**แก้ CSV แล้วรันคำสั่งเดียว ทุกหน้าเปลี่ยนตาม**

## 5. อัลกอริทึมที่ใช้จริง

**เส้นทาง** Dijkstra บนกราฟ 105 ทิศทาง น้ำหนักเป็นวินาที
`cost = walk_seconds × (รถเข็นหรือผู้สูงอายุ ? 1.5 : 1)` และตัดเส้นที่ `is_accessible = false`
ออกทั้งหมดเมื่อเป็นรถเข็น — เขียนซ้ำในทุกหน้าที่ต้องใช้ ด้วยกติกาเดียวกับ `backend/src/domain/graph.js`

**ลำดับขั้น** เงื่อนไข `prereq` ทำให้แผนเป็นกราฟ ไม่ใช่รายการ ขั้นที่อยู่คอลัมน์เดียวกันสลับกันได้
ระบบเลือกขั้นที่ใกล้ที่สุดก่อน ยกเว้นเมื่อขั้นที่มีกำหนดเวลาจะไม่ทัน จึงยกขั้นนั้นขึ้นมาก่อน

**การแบ่งช่วงของแผนที่ผู้ป่วย** ตัดเส้นทางทุกครั้งที่เปลี่ยนชั้นหรือเปลี่ยนอาคาร
หนึ่งช่วงคือหนึ่งหน้าจอ รอยต่อกลายเป็นป้าย "ขึ้นลิฟต์ไปชั้น 3"

## 6. ตัวเลขที่วัดได้จากระบบ

| วัดอะไร | ผล |
|---|---|
| ปิดลิฟต์ B — คนเดินต้องเดินเพิ่ม | +8 เมตร |
| ปิดลิฟต์ B — ผู้ใช้รถเข็นต้องเดินเพิ่ม | **+203 เมตร (25 เท่า)** |
| ปิดลิฟต์ A — ผู้ใช้รถเข็น | **ไปไม่ถึงเลย 32 เส้นทาง** (คนเดินอ้อม 6 เมตร) |
| ปิดทางเชื่อม A→B — ผู้ใช้รถเข็น | ไปไม่ถึงเลย 30 เส้นทาง |
| ยกเจาะเลือดขึ้นก่อนเพื่อให้ทัน 11:00 | เดินเพิ่ม 256 เมตร (ระบบยอมแลก) |
| ระบบช่วยลดระยะเดินไหม | **ไม่ 0%** — ลำดับในแม่แบบสั้นที่สุดอยู่แล้ว (616 ม. เท่ากัน) |
| เส้นทางทั้งวัน | 616 เมตร · เดิน 15 นาที (รถเข็น 22 นาที) · อยู่ในจุดบริการ 135 นาที |

ข้อที่หกวัดแล้วไม่จริง จึงไม่ถูกนำไปอ้างที่ใดในระบบหรือในเอกสารนำเสนอ

## 7. บันทึกการตัดสินใจ

| ตัดสินใจอะไร | ทำไม |
|---|---|
| ผังเป็น CSV ไม่ใช่รูปภาพ | โรงพยาบาลย้ายห้องทุกปี รูปภาพล้าสมัยทันทีและต้องจ้างวาดใหม่ |
| ไม่ใช้ภาพผังของที่อื่นมาดัดแปลง | เป็นงานของผู้อื่น และกรรมการคือคนที่รู้ผังจริง |
| เขียนกำกับทุกหน้าว่าเป็นผังสาธิต | ผิดพลาดเรื่องผังหน้ากรรมการจะทำลายความน่าเชื่อถือทั้งระบบ |
| ภาพประกอบไม่ติดป้ายว่าเป็นภาพถ่ายจริง | ตัวหนังสือบนป้ายในภาพเพี้ยน แสดงว่าเป็นภาพที่ AI สร้าง |
| แผนที่ผู้ป่วยแยกจากผังผู้ดูแลระบบ | ผังรวม 50 จุด 8 ชั้นอ่านไม่ไหวสำหรับคนกำลังรีบ |
| ไม่ทำตู้คีออส | ผู้ใช้ยกเลิกระหว่างทาง จึงถอดออกทั้งหมดไม่ทิ้งเศษไว้ |
| สถานะร่วมผ่านที่เก็บในเบราว์เซอร์ | สาธิตสองหน้าจอเชื่อมกันได้จริงโดยไม่ต้องมีเซิร์ฟเวอร์ |
| ยังไม่ย้าย API ขึ้น Workers | ติด 3 จุดที่พังแบบเงียบ ไม่ใช่ error ชัด เสี่ยงเกินไปก่อนเดโม |

## 8. ข้อจำกัดที่รู้ตัว

- **ผังเป็นชุดสมมุติ** ไม่ใช่ผังจริงของโรงพยาบาลวชิระภูเก็ต
- **ไม่มีการระบุตำแหน่งอัตโนมัติ** ในอาคาร GPS คลาดเคลื่อน 5–20 เมตรและแยกชั้นไม่ได้
  ระบบใช้ตำแหน่งที่เจ้าหน้าที่ยืนยันหรือผู้ป่วยกดบอกแทน
- **ปุ่มสแกน QR ผนังยังไม่ต่อกล้องจริง** แต่ผังมี `qr_token` เตรียมไว้แล้ว 26 จุด
- **ชื่อห้องในฐานข้อมูลมีแค่ไทยกับอังกฤษ** ภาษาอื่นจึงแสดงชื่อห้องเป็นอังกฤษ
- **เส้นทางในต้นแบบเขียนไว้ 15 คู่** จุดอื่นได้คำสั่งรวบข้อเดียว — ของจริงไม่มีข้อจำกัดนี้
  เพราะ Dijkstra คำนวณได้ทุกคู่

## 9. วิธีรันและเผยแพร่

```bash
# หน้าเว็บอย่างเดียว
node app/build.mjs           # สร้างหน้าที่งอกจากข้อมูลใหม่
node scripts/build-site.mjs  # รวมไว้ใน dist/
npx wrangler deploy          # ขึ้น Cloudflare

# ทั้งระบบพร้อมฐานข้อมูล
cp .env.example .env
docker compose up -d --build
docker compose exec api npm run reset
docker compose exec api npm test
docker compose exec api npm run lint:sql
```
