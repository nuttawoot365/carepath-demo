### Sprint 4 — Backend & Database

ยก REST API จาก Express 5 เป็น **NestJS 11 + TypeScript** โดยไม่แตะฐานข้อมูล

- controller **7 ตัว** ครอบคลุม **28 endpoint** — `auth · map · catalog · visits · patient · stations · admin`
- `AuthGuard` + `@Roles()` แทน `requireRole()` เดิม — ตรวจสิทธิ์ที่ API เสมอ
- `DbService` ครอบ `pg.Pool` ด้วย `query()` + `withTransaction()` — **SQL และ 17 ตาราง 3NF ไม่เปลี่ยนแม้แต่บรรทัดเดียว**
- ตรรกะโดเมนเป็นฟังก์ชันล้วน ทดสอบได้โดยไม่ต้องมีฐานข้อมูล
- ย้ายเทสต์เป็น jest — **24 เคสผ่านทั้งหมด**

### Sprint 5 — Frontend & Integration

ยกหน้าเว็บจาก HTML นิ่งหลัง nginx เป็น **Next.js 15 App Router + TypeScript**

- **4 หน้า** ที่ต่อ API จริงเขียนใหม่เป็น React — `/login` `/registrar` `/station` `/patient`
- อีก **7 หน้า** ยังเป็น HTML นิ่งใน `public/` ที่สร้างจาก `data/` เหมือนเดิม
- โทเคนการออกแบบที่เคยคัดลอกซ้ำในหัวไฟล์ HTML ทุกใบ รวมเหลือ `globals.css` ที่เดียว
- QR generator เลิกพึ่ง cdnjs ย้ายมาใช้ npm
- **ลิงก์เดิมไม่พัง** — `/patient-mobile.html?t=` redirect ไป `/patient?t=` บัตรคิวที่พิมพ์แล้วยังสแกนได้

## ภาคผนวก — ผลรันจริง 11.15 น.

รันซ้ำทั้งเส้นหลัง reset ข้อมูล เพื่อยืนยันว่าตัวเลขในเอกสารนี้มาจากระบบจริง ไม่ใช่ของเก่า

```
1. เวชระเบียนเปิด visit (รถเข็น + ผู้สูงอายุ)
   บัตรคิว A-001 · รหัสใต้ QR A001-MAH · สมชาย
   ขั้นตอน 7 ขั้น · เบาหวานรายเก่า — ตามนัด

2. ผู้ป่วยบอกว่าอยู่จุดพักคอย → คิดเส้นทางใหม่ทันที
   เส้นทาง 147 เมตร · 371 วินาที · 9 คำสั่ง
     ⬆ ออกจากจุดพักคอยรอผล เดิน 6 เมตร ถึงห้องเจาะเลือด ขวามือ ข้างตู้น้ำดื่ม
     ➡ เลี้ยวขวา เดิน 24 เมตร ถึงลิฟต์ B
     ▼ ลงลิฟต์ B ไปชั้น 2

3. จอจุดบริการกดสามปุ่ม
   arrived 200 · in_progress 200 · done 200

4. หน้าผู้ป่วยเปลี่ยนตามเอง
   ขั้นถัดไป: เจาะเลือด · ห้องเจาะเลือด
   แจ้งเตือน: ยื่นบัตรและยืนยันการนัดเรียบร้อย — ดูขั้นถัดไปได้เลย

5. แพทย์สั่งเอกซเรย์เพิ่ม → จัดลำดับใหม่ให้เอง
   1. ยื่นบัตรและยืนยันการนัด      5. พบแพทย์
   2. ชั่งน้ำหนัก วัดความดัน       6. เอกซเรย์ปอด   ← แทรก
   3. เจาะเลือด                   7. ชำระเงิน
   4. รอผลตรวจ                    8. รับยา
```

**ข้อ 5 คือหลักฐานว่า topological sort ทำงานจริง** — ขั้นที่แทรกไปอยู่หลัง "พบแพทย์"
(เพราะต้องมีคำสั่งแพทย์ก่อน) และก่อน "ชำระเงิน" (เพราะต้องจ่ายหลังรู้รายการทั้งหมด) โดยไม่มีใครบอกตำแหน่ง

หลังรันเสร็จ reset ข้อมูลกลับแล้ว — ไม่มี visit ทดสอบค้างในระบบ
